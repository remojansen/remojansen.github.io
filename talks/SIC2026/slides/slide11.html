Good Friction vs. Bad Friction

Not all friction is equal. Some slows you down and invites AI to hallucinate. Some catches mistakes before your users do.

Bad Friction (Eliminate)

  • Flaky unit tests that cry wolf until everyone ignores them
  • Stateful distributed systems nobody can reason about
  • Unpredictable side effects hidden deep in the call stack
  • Shared mutable state across service boundaries

Good Friction (Adopt)

  • Type errors that catch null references before production
  • Foreign keys that make invalid states unrepresentable
  • Type-safe protocols (protobuf) that catch breaking changes at compile time
  • Ownership rules that prevent memory leaks at compile time
  • Effect systems that make side effects visible in the type signature
