The DX Paradox

The exact fluid design setups we chose to make human typing fast now create extreme drag for AI-assisted workflows:

  • Dynamic types: AI has no blueprint of your system — it guesses signatures, invents properties, and generates code that looks correct but breaks at runtime. Every output requires manual verification.
  • Schema-less databases: Without declared relationships and constraints, AI generates queries against assumed structures. No FK, no enums — data corruption happens silently.
  • No explicit side effects: Without explicit side effects, we can't be sure AI handles them correctly — making human code review inevitable.
  • No concurrency model: Without explicit boundaries for parallel computation (like the actor model), AI generates code with shared mutable state, race conditions, and deadlocks.
  • No architecture tests: Without tests enforcing structural boundaries and dependency rules, AI crosses layers, imports forbidden modules, and breaks architectural intent — while unit tests still pass.
  • No explicit memory ownership: Without ownership rules (like Rust's borrow checker), AI generates memory leaks and use-after-free bugs that only surface in production.
